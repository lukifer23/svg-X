# Engineering audit — 2026-11-16

This audit covers the current unreleased `main` branch after the recovery work.
It is an implementation record, not a release claim.

## Outcome

The application has real B&W, color-region, and centerline pipelines; all
exports serialize the authoritative `VectorDocument`; browser and packaged
Electron conversion work; the frozen dependency tree has zero known npm
advisories; and the production batch worker path meets its throughput and
memory gates. No production conversion path is mocked or stubbed.

The audit found and fixed two release-blocking production defects:

1. Concurrent color jobs could deadlock by each reserving one band worker and
   waiting for another. A conversion now reserves its complete band set
   atomically. Queued aborts reject immediately, active aborts terminate and
   replace the worker, and the pool is capped at four workers.
2. The first CSP revision blocked `fetch(blob:...)`, which is how a selected
   browser/Electron image reaches the decoder. `connect-src` now permits only
   same-origin and local `blob:` input (plus development WebSockets in the HTML
   policy). The clean packaged smoke test caught the failure and passes after
   the fix.

## Performance

- Exact single-thread color optimizations retain identical serialized SVG
  hashes on the benchmark corpus.
- The production Chromium benchmark now completes instead of timing out.
- On the controlled four-logical-CPU profile, the three-sample medians were
  377.4 ms sequential versus 236.5 ms pooled for eight real 512 x 512 color
  conversions, a **1.60x** throughput gain.
- Peak and settled JS heap growth were 90.8 MiB, below the 256 MiB ceiling.
- The full concurrent browser run independently measured 1.62x, providing a
  second end-to-end signal.
- Interactive jobs remain prioritized over batch jobs. Worker counts are
  bounded; no runtime-generated worker source or base64 image transport is
  used.

See `results/PERFORMANCE.md` for the stage-level history and methodology.

## Security

- Updated direct dependencies remove the prior production advisories; `npm run
audit:deps` reports zero vulnerabilities.
- Electron 45 runs with sandboxing, context isolation, and no Node integration.
- IPC validates the sender and uses opaque directory grants rather than
  renderer-supplied paths.
- Input extensions, encoded bytes, decoded dimensions, output bytes, child
  paths, and native export formats are bounded or allowlisted.
- Output collision handling uses exclusive creation and does not overwrite
  existing files.
- Navigation is exact-origin; permission checks and requests are denied by
  default; only credential-free HTTPS URLs may leave the app.
- CSP, opener/resource isolation, permission policy, no-referrer, and no-sniff
  headers protect the packaged origin. LAN mode does not enable permissive
  CORS.

## Honest remaining release work

- Hosted CI must pass on the pushed commit across Windows, macOS, and Linux.
- Code signing, macOS notarization, and clean-machine installer behavior are not
  proven by unsigned package smoke tests.
- HEIC/HEIF support still depends on the target Sharp/libvips codec build.
- DXF intentionally uses adaptively flattened R12 polylines rather than native
  splines.
- Color vectorization is an error-bounded approximation; photographs and
  antialiased subpixel edges are not lossless.
- Issue #37 should close only when a color-capable binary is actually released.

These are release/distribution limits, not hidden production stubs. They are
kept explicit so a green source tree is not misrepresented as a published,
signed, clean-machine release.
